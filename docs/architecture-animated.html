Step 1 — Identity. The client presents an Entra token for audience api://246e2a64…. APIM verifies signature, issuer and audience. No valid token → 401, before anything else runs. Step 2 — Authorization. The team subscription key must agree with a group claim in the token. Using another team’s key → 403 wrong_team. Leaving a team revokes access on the next token. Step 3 — Cost control. APIM enforces that team’s token / request / daily quota. Marketing = 1,000 TPM, Engineering = 50,000 TPM, Finance = 20,000 TPM. Over‑limit → 429, protecting the shared model and the budget. Step 4 — Safety. One shared content‑safety + jailbreak shield screens the prompt before the model is ever called. Harmful or prompt‑injection content → 400 content_filtered. Step 5 — Key‑less call. APIM strips any client key and injects the credential itself — a managed‑identity token for Foundry, or the stored vendor key for Anthropic/Bedrock/Vertex. The app never sees a model credential. Step 6 — Response & audit. The model’s answer returns through APIM, which records team, cost center and tokens to App Insights / Log Analytics for chargeback and audit — then hands the response back to the app.
